# Full delegated task

## Objective and scope
Deliverable, included files/IDs, exclusions, and objective-level failure conditions.
Explain why this work can be bounded independently; serialize coupled decisions.

## Context and authoritative inputs
Fresh or exact-session continuation, predecessor job and reconciliation outcome.
Carry verified decisions, interfaces and rationale; identify rejected assumptions.
Give absolute working directory and authoritative source paths. Separate source
evidence, generated interpretations and history. For blind review omit prior verdicts.

## Starting state and dependencies
Base revision and relevant uncommitted snapshot/patch/hashes. Read dependencies,
predecessor artifacts, expected interfaces/output/failure behavior, downstream
consumers, shared services/databases and their ownership. State which inputs must
remain stable and how the parent checks freshness and integration.

## Write ownership and authorization
Exact allowed code/test/output paths, summary, indexed findings report and optional
progress path, all outside the installed bundle. Preserve pre-existing edits and
earlier drafts. Never overwrite helper records or parent acceptance. Include project
rules, approved model/provider/destination and execution/resource limits (or launch
record reference). Do not launch other agents/inference, contact new endpoints,
commit or publish unless explicitly authorized.

## Coverage, assumptions and staged checks
Enumerate units to inspect and observable acceptance criteria before seeing answers.
Distinguish exhaustive coverage from samples. Identify assumptions, contradictions,
negative cases and gaps. Define an early representative check before expansion,
final verification commands and objective-level reasons to reject completion.

## Escalation and stop
Report the concrete dependency on missing input, stale interface, uncertain source,
scope growth, conflicting instructions or repeated failed correction. Stop the
dependent part; preserve useful in-scope work. A tier change grants no authority.

## Reports and final return
Summary: completed/partial/blocked/no supported finding; actual coverage and gaps;
decision-relevant findings/changes, contradictions, uncertainty and failed checks;
verification performed or omitted; evidence pointers and next action. Aim for 400
words, exceeding this when needed for material caveats. Give stable finding IDs
and an index inside the report, source path/symbol/line/section and inspected state.
Generated summaries are not original evidence. An optional progress file reports
only new coverage, provisional findings, blockers and next step at checkpoints;
it is observed by polling, not a notification channel. Final text names summary
path and blockers. Only the parent records acceptance.
