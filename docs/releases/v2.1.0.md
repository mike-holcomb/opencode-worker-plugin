Publication is pending; v2.0.0 remains the published release until v2.1.0 is tagged

`execution_supported: false` and the exact trusted-workspace opt-in required.

## Changes

### Cancellation intent survives concurrent observation (#2, PR #5)

An in-flight observation can no longer restore `running` or `waiting_input`
after cancellation is durably recorded. Active executions with cancellation
intent continue through cancellation reconciliation, including recovery of
previously stranded intent. A normal completion that wins the cancellation race
keeps its completed or failed outcome.

### Stop confirmation and owned-worker recovery (#4, PR #6)

Cancellation refreshes and expires pending requests from exact-turn observations.
The parent can deny an exact pending permission until forced termination starts;
reply ambiguity does not trigger automatic resubmission. Fresh abort proof is
renewed after backend recovery rather than inferred from a durable acknowledgement.
Bounded `cancellation_diagnostic` events explain stop status, active-tool and
pending-request counts, backend availability and recovery blockers.

If stop is unconfirmed after 30 seconds, the supervisor terminates its exclusively
owned managed worker process group: SIGTERM with up to five seconds for exit,
then SIGKILL with another five seconds. Reservations remain held until exit is
proven and evidence finalization completes. Worker identity, termination intent
and exit proof are durable. Loss of the original process handle remains explicitly
unresolved; a replacement worker cannot prove the original stopped. Attached
servers and subprocesses that leave the managed process group are outside this
recovery mechanism. Existing SQLite state receives a snapshot before schema
repair, and backup failure stops the upgrade.

### Incremental worker checkpoints (#3, PR #7)

Managed workers publish bounded milestones through native `report_progress`.
The new read-only `opencode_get_progress` brings the parent toolkit to eleven MCP
tools. Reads require an exact execution identity and return unseen updates after
an opaque cursor. Repeated reads with an advanced cursor return empty deltas;
snapshots are explicit. Waits can wake for progress and return compact hints.

Checkpoints are advisory worker claims held in bounded supervisor memory. Restart,
disconnect, attribution failure, retention or eviction produce explicit gaps and
recovery cursors. This implements the issue's revised memory-first design;
checkpoints are not a durable conversation replay. Payload, rate, per-execution
and aggregate-memory bounds apply. Final reports, lifecycle state and parent
acceptance retain their independent durable contracts.

The native tool is staged in a private, hashed directory, with execution attribution
verified from exact session/message/tool metadata. Managed workers isolate custom
tool discovery and disable project configuration discovery. See
[progress](../../plugins/opencode-agents/docs/progress.md) for limits and usage.

## Install and upgrade

Install Node.js 24.15 or later within 24.x, and OpenCode **1.19.0** separately.
The SDK is pinned to **1.19.0**; the binary/SDK/OpenAPI pair must match exactly.
The published v2.0.0 tag targeted 1.18.35 and displayed internal version
`2.0.0-dev.0`. Both package manifests now agree with the release version.

Before upgrading, reconcile active tasks, drain the old supervisor and back up
its state database and reports. Update the plugin and OpenCode together; retain
matching runtime/database backups for rollback. Do not run old and new
supervisors against one state directory.

After publication:

```bash
codex plugin marketplace add mike-holcomb/opencode-worker-plugin --ref v2.1.0
codex plugin add opencode-agents@opencode-worker-plugin
```

Start a fresh Codex session. Configure the authorized provider/model and exact
trusted-workspace opt-in as described in
[installation and rollback](../../plugins/opencode-agents/docs/installation.md).
The release assets are a prebuilt plugin ZIP, per-file SHA-256 manifest and
checksum sidecar; end users need no runtime `npm install`, Python or compilation.

## Validation and limits

On macOS arm64 under Node 24.21.0, the candidate passed:

- Runtime build and executable bundling; all 153 runtime tests, including deferred
  observation cancellation races, fresh abort proof, request reconciliation,
  owned-worker termination, cursor gaps and bounded checkpoint transport.
- Five release-runner tests, nine packaging tests and five evaluation-harness tests.
- All twelve frozen scenarios: 69 checks and 31 fixture files, without inference.
- Allowlisted 75-file archive construction and relocated read-only installed smoke:
  eleven MCP tools, unchanged bundle bytes and runtime state outside the bundle.
- Manifest/package/lock version agreement and documentation link checks.

The initial sandbox run could not bind local fixture sockets. Runtime and
release-runner tests passed outside that restriction; an escaping release-note
link was then fixed and packaging passed on rerun. These candidate checks do
not imply provider inference or marketplace installation.

The main-targeted PR runs the same non-inference platform suite on macOS 15 and
Ubuntu 24.04 under Node 24.15.0 and 24.21.0. Final-tag marketplace installation
and final-merge asset verification remain publication steps.

Existing local October 15 evidence on OpenCode/SDK 1.19.0, Node 24.19.0 and the
authorized Glimmer route covers checkpoints before completion, empty incremental
deltas, hint-only waits, valid final reporting, same-session continuation,
supervisor restart and cancellation after backend restart. Permission denial was
delivered but the fixture timed out without a final report. These results do not
certify successful completion of that fixture or full cross-platform execution.
See [progress validation](../../plugins/opencode-agents/docs/progress.md) and
[historical validation](../../plugins/opencode-agents/docs/validation.md).

Full host/plugin discovery containment, Linux live/WSL2 operator evidence and
remaining evaluation outcomes are still open. The historical 1.18.35 plugin-loading
race remains relevant boundary evidence; current launch isolation does not prove
complete containment. Attached execution and native questions remain disabled.
